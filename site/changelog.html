Current cycle — Cycle 6

System-wide hot-path optimisations: arena allocator, 32-byte NEON, runtime parallel, and FPQ-X algebra.

Six targeted additions this cycle, all in the critical path. lt_core.c's JSON codec eliminated ~90 malloc sites with a 64 KB inline arena and bulk-free on scope exit. SIMD string scanning moved from per-character dispatch to AVX2/NEON 32-byte batches. bonfyre-runtime gained a parallel subcommand that forks arbitrary command groups concurrently and collects exit codes. bf_mmap got a stateless MADV_WILLNEED prefetch API aligning with the OS page cache rather than duplicating it. The FPQ-X algebra layer shipped as a standalone library with a LoRA compressed-domain example and tests.

lt_core.c — LtArena allocator

Zero per-character allocation in the JSON codec

Previous JSON encode paths called malloc/realloc for every appended character via grow_text_buf and append_text_char. Replaced entirely with LtArena: a 64 KB inline slab with pointer-bump allocation (8-byte aligned), heap spill for payloads exceeding the slab, and lt_arena_reset that bulk-frees everything in O(1). Functions lt_encode_v1, lt_encode_v2, and lt_encode_v2_interned all allocate through the arena; the old per-object free(vals[i].val) loops are gone. ~90 malloc/realloc call sites eliminated.

Why it matters: Repeated JSON encode passes — compress many small documents in a loop — no longer spike the heap allocator. Memory use is bounded by the 64 KB inline slab for typical payloads. Heap fragmentation on long-running pipeline stages is eliminated for this path.

lt_core.c — SIMD JSON scanner

lt_json_skip_string + lt_json_scan_ws with NEON / AVX2 / SSE2 dispatch

lt_json_skip_string: processes 32 bytes per iteration on NEON (dual vld1q_u8 + vorrq_u8 early exit), 32 bytes via AVX2 movemask, 16 bytes via SSE2, scalar fallback — finds the closing " or backslash without touching the heap. lt_json_scan_ws: inline whitespace and delimiter skip (,, :, \n, \t, space). parse_next_value_ar wires both into arena-aware token extraction: one lt_arena_strndup per value, zero intermediate allocations.

Why it matters: JSON parse throughput on the V1/V2/Interned encode paths scales with SIMD width, not character count. Large documents that previously caused significant allocator pressure now scan at memory bandwidth.

bf_simd.c — 32-byte NEON scan

find_char_simd and find_char2_simd: 2× throughput on ARM

Both functions previously processed 16 bytes per iteration via a single vld1q_u8. Upgraded to 32 bytes per iteration: load two 16-byte vectors, OR their match masks (vorrq_u8), and only enter the scalar hit-resolution branch when either register matches. Mop-up loop handles trailing 0–31 bytes. The change is transparent to all callers — same signature, same semantics, double the throughput on NEON hardware.

Why it matters: find_char_simd is in the hot path for JSON field scanning, base64 delimiter search, and CSV parsing across 53 binaries. Doubling iteration bandwidth at zero API cost is an unconditional win on Apple Silicon and ARM servers.

bf_mmap.c — bf_mmap_prefetch

Stateless MADV_WILLNEED batch hint — no pool, no LRU, no hidden state

New function bf_mmap_prefetch(const char * const *paths, int n): iterates a list of file paths, mmaps each with MAP_SHARED, issues MADV_WILLNEED, and immediately munmaps. The kernel page-faults the data in asynchronously; by the time the pipeline stage opens the file, it's already warm in the page cache. Non-fatal per-path, returns a count of paths successfully advised. No slot array, no LRU, no shared mutable state — the OS page cache already solves that problem.

Why it matters: Pipeline stages that read a batch of artifacts can issue prefetch hints for the entire batch before processing starts. The operation is idempotent and safe to call from any stage without coordination. An earlier pool-based implementation was reverted — it duplicated the OS page cache and accidentally overrode the existing MADV_SEQUENTIAL hint on linear read workloads.

bonfyre-runtime — parallel subcommand

Fork up to 64 arbitrary command groups concurrently, collect all exit codes

New parallel subcommand added to bonfyre-runtime. Syntax: bonfyre-runtime parallel [-- cmd args...].... Parses -- delimiters from argv, forks each group simultaneously via fork()/execv(), collects with waitpid(pid, &st, 0) per child, returns 0 only if every child exited 0. Maximum 64 groups (PAR_MAX_GROUPS). Sends SIGTERM to already-forked children on fork failure.

Why it matters: Stages that are independent but not encoded in a bonfyre-run recipe can now be parallelised with one command instead of a shell background job mess. Verified: 3 × /bin/sleep 0.1 completes in 0.111 s total.

bonfyre-runtime parallel -- process-a input.wav -- process-b input.wav -- process-c input.wav
fpqx_algebra — FPQ-X algebra library

Standalone algebra primitives for compressed-domain operations

New library (fpqx_algebra.h / fpqx_algebra.c) providing low-level algebra over FPQ-X alignment matrices: matrix–vector multiply, matrix–matrix multiply, Frobenius norm, and dot product over the 16×16 float32 alignment tensors produced by bonfyre-fpqx. Includes a LoRA compressed-domain example (examples/lora_compressed_domain.c) demonstrating low-rank adapter application without decompressing weights, and a full test suite (tests/test_fpqx_algebra.c).

Why it matters: Tooling that needs to compose or inspect FPQ-X alignment tensors can link the algebra library directly rather than parsing binary files. The LoRA example shows that fine-tuning adapters can be applied in the compressed domain — no full-precision weight expansion needed during adapter composition.

Cycle 5

Transform families, geometry routing, ONNX layer surgery, and structured inference.

Seven additions this cycle: bonfyre-model v1.1.0 adds a geometry-aware transform family registry and automatic routing. A 72-run diversity matrix across ag_news × cnn_dm promoted three families (T04, T15, T16) to production and dropped T17. Four new C binaries — bonfyre-layer, bonfyre-fpqx, bonfyre-sli, plus ONNX input for bonfyre-quant and iterative loop support in bonfyre-runtime — complete the BQFP inference pipeline end to end.

bonfyre-model v1.1.0

Transform family schema + geometry router

New schema columns: transform_family, geometry, geometry_condition, layer_frag_spec, mean_f1. Live migration via ALTER TABLE on open — existing databases upgrade in place. New family [name] command lists models by family. New route <corpus_stats.json> command reads corpus statistics, evaluates geometry predicates (avg_doc_len > 500), and returns the highest-F1 family whose condition passes. JFIELD macro extended to parse unquoted numeric values.

Why it matters: The model registry now knows what kind of input a transform expects. Route with bonfyre-model route corpus_stats.json — T16 selects on long-form corpora; T04/T15 route to general content. No manual selection.

72-run diversity matrix

T04 · T15 · T16 promoted — T17 dropped

72 evaluation runs across ag_news × cnn_dm × 3 corpus scales with F1-vs-consensus and latency-ratio gates. Results: T04 Topic Mapper (global, mean F1 = 0.914, 10/10 pass, stability 0.895), T15 Keyword Structure (global, mean F1 = 0.911, 12/12 pass), T16 Paragraph Boundary (long-form only, mean F1 = 0.931, 5/8 pass, activates when avg_doc_len > 500). T17 Readability Complexity dropped — avg F1 = 0.647 across 12 experiments; lexical readability features produce diffuse clusters insufficient for collapse geometry.

Why it matters: Three production-grade transform families are live in the registry with verified F1, geometry, and routing conditions. T16's conditional geometry is the first example of corpus-adaptive routing in the stack.

bonfyre-quant — ONNX input

Compress any ONNX model to BQFP format

New compress <model.onnx> <output.bqfp> [--bits N] command auto-detects ONNX files and encodes all initializer tensors to BQFP. New inspect <file.bqfp> prints full tensor and codebook structure. A minimal protobuf parser in C (zero external deps) handles both raw_data and float_data initializer formats. BQFP format: E8 lattice INT8 per 256-element block, 16-entry tile codebook per tensor, 280 bytes/block. Per-tensor headers carry element count, block count, eff_k, and 256-byte tensor name.

Why it matters: Any ONNX model — PyTorch export, HuggingFace, scikit-learn — is now a first-class citizen in the BQFP pipeline. The compression step runs in a single sub-400 KB C binary with no Python bridge.

bonfyre-runtime — loop N

Iterative pipeline execution with artifact chaining

New loop <N> <binary> [args...] command. Creates per-iteration output directories (base-1, base-2, … or /tmp/bonfyre-loop-PID-I if no --out). Replaces --out DIR with --out DIR-I and chains artifact.json from the previous iteration as --in for the next. Halts immediately on non-zero exit. Works with any binary — not only Bonfyre tools.

Why it matters: Iterative refinement passes — repeated scoring, re-embedding, or progressive summarisation — no longer need shell scripts. Loop chains artifacts automatically and stops on failure, with a clean output tree for post-run inspection.

bonfyre-layer — C port

ONNX layer surgery in pure C

Full C port of the Python bonfyre-layer binary (~830 lines, no Python runtime dependency). Commands: inspect, layers, pull-layer N:M, pull-head N, pack-transform, schema. pull-layer extracts NodeProto slice with all required initializers via a dynamic write buffer, wraps in a new ModelProto with opset 17, and writes a SHA-256 artifact manifest. Minimal ONNX protobuf reader/writer — parse_graph, parse_node, WBuf dynamic write buffer.

Why it matters: Layer extraction, hashing, and registration in the transform family registry runs entirely in a ~200 KB binary. No NumPy, no ONNX Python package, no virtual environment. bonfyre-layer pull-layer 0:2 model.onnx fragment.onnx and you have a layer fragment with verified SHA.

bonfyre-fpqx — cross-family alignment

Align codebooks between transform families

Reads two BQFP files, greedy-matches codebook tiles by cosine similarity (threshold 0.5), then solves a 16×16 least-squares alignment matrix via Gauss-Jordan elimination with 1e-6 regularisation. Writes fpqx_alignment.bin (FPQX magic + 256 float32) and fpqx_alignment.json. Commands: align <a.bqfp> <b.bqfp> --out DIR, eval, inspect. Anchor pairs with cosine below threshold are discarded; underdetermined systems fall back to identity.

Why it matters: Chaining T04 → T16 without alignment produces representation drift. bonfyre-fpqx computes the rotation matrix that maps T04's codebook space into T16's so sequential inference stays coherent across families.

bonfyre-sli — Structured Layer Inference

Decode BQFP weights and run transform inference in C

Full BQFP decode + inference pipeline: e8i int8 → lattice scale → tile residual correction by codebook lookup → μ-law unwarp (β = 8) → inverse FWHT → sign undo → float32 weight matrix. Applies matrix as a linear projection over input embedding vectors. Commands: run (single family), chain (multi-family, e.g. --chain T04:T16 with optional FPQx alignment), route (calls bonfyre-model route to auto-select family), bench, inspect. Input/output wire format: [n:u32][dim:u32][float32×n×d].

Why it matters: The full loop — corpus stats → geometry routing → BQFP decode → transform apply — runs in a single C binary with no Python and no GPU. bonfyre-sli route --stats corpus_stats.json --in embeddings.bin --out results/ is the complete pipeline.

Cycle 4

Pipeline registry, DAG executor, and 10 built-in recipe codes.

Three new binaries that make the whole stack runnable in one command: bonfyre-recipe maintains a content-addressed SQLite registry of named pipelines, and bonfyre-run resolves a recipe code, builds a dependency graph, and executes stages level-parallel with Ed25519-signed run manifests on every invocation.

New binary — bonfyre-recipe

Content-addressed pipeline registry

SQLite WAL-mode store with FTS5 full-text search, SHA-256 content addressing, and 10 built-in recipe codes (A1–A3, M1, P1–P2, V1, R1, L1, G1). Commands: list, show, search, validate, add, init. Custom recipes stored as JSON and loaded alongside built-ins.

Why it matters: There's now a single authoritative source for what a pipeline is. Every team member, every CI step, and every audit trail references the same recipe hash. No drift between environments.

New binary — bonfyre-run

DAG executor with level-parallel stages

Resolves a recipe code, assigns topological dependency levels, forks up to 8 stages concurrently per level, substitutes {input}/{out} variables, and writes a signed run-manifest.json on every run. Flags: --dry-run, --batch, --resume, --from-stage, --to-stage, --tier.

Why it matters: Running the full audio-to-publish pipeline went from a 23-step manual sequence to bonfyre-run A3 episode.wav --tier pro. Every run is reproducible, auditable, and partially resumable after failure.

Registry — 10 built-in recipe codes

A-series, M, P, V, R, L, G series

A1 (audio quick brief), A2 (audio archive), A3 (full pipeline, 23 stages), M1 (media/podcast), P1 (proof bundle), P2 (verified publish), V1 (verified brief with Ed25519 proof), R1 (repo onboarding guide), L1 (revenue event track), G1 (API gateway policy check). All 10 discoverable via bonfyre-recipe list.

Why it matters: The shortcodes are the public API of the stack. Every recipe page, app card, and layer page now surfaces the relevant code so readers can immediately run what they're reading about.

New binary — bonfyre-model

AI model dependency manager

SQLite registry of model deps mapped to recipe codes. 10 built-in records (Whisper base/medium/large-v3, Llama 3 8B/70B, Llama 3 8B FPQ, nomic-embed-text, bge-reranker, pyannote, silero-vad). Source chain: swarm:// → file:// → s3:// → hf:// (plain HTTPS GET) → https://. SHA-256 content verification on every pull. bonfyre-model pull --recipe A3 pulls all deps for a recipe in one command. No Python SDK dependency on HuggingFace — models switch to any mirror by adding a source entry.

Why it matters: Model files were the last manual step in pipeline setup. A 3 GB Whisper model had no registry, no version tracking, and no fallback source. bonfyre-model closes that gap — every recipe now has declared model deps, a verified hash, and a multi-source pull chain that doesn't depend on any single vendor.

Cycle 3

Transport, runtime, compression, and private inference.

Six additions this cycle: peer-to-peer artifact distribution, QUIC transport, a shared-nothing API reactor, hot-load pipeline stages, a zero-copy LMDB cache layer, and SIMD decode plus homomorphic scoring for the FPQ model compression layer.

New binary — BonfyreSwarm

BitTorrent v2 artifact CDN

SHA-256 piece trees, 256 KB pieces, and local peer knowledge maintained in LMDB. Gate and Meter hooks baked in — access to swarm content can be quota-guarded without a separate policy service.

Why it matters: Artifact bundles don't need a CDN vendor. They self-distribute to peers who already have pieces. Large model bundles and archive packs distribute to a team without a CDN subscription or S3 bucket.

New binary — BonfyreDistribute

QUIC family streams with fountain codes

Artifact families multiplex over QUIC with surface-first priority and reconnect logic. LT-code fountain coding means up to 33% packet loss is recoverable without a full retransmit.

Why it matters: Field researchers syncing archives over satellite links no longer get incomplete transfers on lossy connections. BonfyreDistribute + fountain codes make lossy sync reliable.

Runtime addition — bf_reactor

Shared-nothing API runtime

Per-core event loops with faster HTTP/1.1 decode via bf_picohttpparser, SSE push support, and per-reactor mimalloc heaps. 4,096 concurrent connections per reactor core.

Why it matters: Every binary that exposes an HTTP surface — BonfyreAPI, BonfyreProxy, BonfyreCMS — runs on bf_reactor. Per-core shared-nothing means no lock contention across cores. Throughput scales linearly with core count.

Pipeline addition — BonfyrePipeline hot-load

Swap stages without rebuilding

32-stage plugin registry, 16 live A/B pairs, and a coroutine-based execution path with channels and deadlines. Drop a new stage binary into the directory, call the hot-swap endpoint. The swap is atomic at the function pointer level.

Why it matters: Iterating on a transcription cleanup pass or a brief extraction prompt no longer requires restarting the pipeline. Swap the stage in; the next artifact routes through the new code. A/B pairs make staged rollouts safe.

Runtime addition — bf_lmdb + bf_flatbuf

Zero-copy read-hot cache

Repeated artifact fetches pointer-cast directly into LMDB mmap pages. bf_flatbuf manifest fields are accessed via direct struct overlay — no JSON parse overhead on repeated reads. 512 MB default map, 4 named sub-databases.

Why it matters: Pipeline stages that read the same brief multiple times (BonfyreRepurpose generating 4 formats) do zero heap allocation per read after the first. At high batch volumes, this is the difference between memory pressure and not.

FPQ addition — SIMD BP128 + HE-SLI

Faster decode and private scoring

SIMD BP128 decodes 128 E8 INT7 values per instruction block. HE-SLI adds depth-1 homomorphic encrypted linear scoring — inference stays in the encrypted domain for privacy-critical flows.

Why it matters: SIMD BP128 accelerates FPQ decode on every inference call. HE-SLI enables scoring pipelines where the input data is sensitive — the model scores over encrypted representations, not cleartext. Legal and health data pipelines specifically.

26-module runtime

The shared substrate

bf_reactor, bf_lmdb, bf_mmap, bf_hashmap, bf_json, bf_msgpack, bf_lz4, bf_crypto, bf_bloom, and 17 more. 180 KB total. Every binary links the same library. A security fix propagates to all 53 binaries at the next build.

FPQ baseline

INT8 quantisation with polynomial correction

4× compression of FP32 model tensors to INT8 with polynomial correction coefficients. 99.97% cosine similarity to the original. First 4 models published on HuggingFace. GPU optional — CPU inference via SIMD decode on Apple Silicon and x86 AVX2.
